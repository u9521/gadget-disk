# Agent Note: 槽位模型与镜像上下文自动修正

Status: implemented
Category: architecture

## Problem

系统存在四处与底层内核事实脱节的问题：

### 一、守护进程诊断日志缺失

`gdd` 早期由 `setsid` 派生且标准流重定向至 `/dev/null`，其内部的报错与调试日志无法持久留存；同时日志文件与运行期临时文件（socket、文件锁、状态缓存）混杂，缺乏清晰的生命周期边界划分。

### 二、前端镜像路径输入失控

WebUI 早期允许手动输入镜像绝对路径，破坏了镜像统一归属 `images/` 目录的管理契约，引发越界访问、清理遗漏及上下文无法自动修正等问题。

### 三、LUN 生命周期模型混淆

UI 将每一次操作视为单次挂载请求，而内核中实际维护的是持久化的 `lun.N` 目录与属性节点。卸载操作在内核中仅清空 backing file，目录与模式属性仍然存留；原 UI 逻辑将其视为整体销毁，导致重新挂载需重复配置。

### 四、镜像文件 SELinux 上下文阻断

内核 `file-storage` 线程对镜像文件的访问受系统上下文约束，若仅具备读权限会导致 Host 端写入被内核静默抑制。须在挂载请求触发时由 CLI 显式校验并修正安全标签。

## Proposal

### 一、分离独立 `logs/` 目录与标准化日志格式

诊断输出从 `run/` 分离至专有 `logs/` 目录（权限 `0700`），实现多进程日志物理隔离：`cli.log`、`gdd.log`、`service.log`、`serve.log`。统一格式为 ISO8601 + 日志级别 + 消息正文，单文件达到 256 KiB 自动轮转保留一代（`.1`）。`gdd` 日志路径由 CLI 启动时通过 `--log-file` 注入。

### 二、WebUI 镜像选择收敛至预设目录

前端镜像字段改为受控 `<select>` 下拉选择，选项来源于 `images/` 目录的扫描结果，保证所选镜像均处于受控管理边界内。

### 三、槽位状态模型

将 LUN 抽象为持久化“槽位”，如实映射内核状态：

- **已挂载 (Mounted)**：展示后备镜像、模式与 INQUIRY 标识，支持介质“弹出”；
- **空闲 (Idle)**：槽位目录及配置参数保留，支持就地更改参数重新挂载，或显式删除槽位。

| 操作 | 语义契约 | 内核调用效果 |
|---|---|---|
| `unmount --lun N` | 弹出介质，保留槽位 | 清空 `lun.N/file`，保持目录与参数不变 |
| `delete-slot --lun N` | 彻底移除槽位 | `rmdir lun.N` 并重绑 UDC |

`lun.0` 为内核随 function 固有创建，禁止删除；`delete-slot --lun 0` 显式返回 `invalid_argument` 错误。

### 四、镜像上下文自动校验与修正

挂载前对目标镜像读取 `security.selinux` 属性：非 SELinux 设备跳过；非 `images/` 目录下的外部路径仅告警且严禁修改；`images/` 目录下的镜像若安全上下文不匹配，则自动修正为 `media_rw_data_file`。CLI 与 REST 后端共用同一处理逻辑。

## Alternatives considered

- **合并多进程日志输出**：否决。跨进程混合写入会导致事件交织，增加因果排查歧义。
- **依赖调用端重定向**：否决。易因派生时序或环境差异导致诊断信息静默丢失。
- **UI 隐藏空闲槽位**：否决。违背内核实际存在 `lun.N` 目录与参数的事实，破坏参数可复用性。
- **卸载时全量删除 `lun.N` 目录**：否决。内核需要重新绑定 UDC 才能彻底删除目录，会引发总线连接抖动，并造成已配参数丢失。
- **在 `sepolicy.rule` 中为 kernel 域动态授权**：实测无效，内核 AVC 拦截依旧存在，修改文件自身安全标签为唯一可靠方案。
- **以 `lun.N/ro` 属性作为可写判定依据**：否决。该属性在内核写入被拒时仍可能回显 0，判据必须以写入后镜像校验和变化为准。

## Acceptance criteria

1. `logs/` 目录建立在标准布局中且赋权 `0700`。
2. 日志轮转与格式单测通过。
3. 槽位语义验证：
   - `unmount --lun 1` 后介质清空但目录与参数存留；
   - 后续挂载直接复用空闲槽位且不触发 USB 重绑；
   - `delete-slot --lun 1` 成功删除目录并维持 UDC 绑定；
   - `delete-slot --lun 0` 被正确拦截拒绝。
4. 镜像上下文单测通过，真机端到端写入验证校验和发生改变。
5. 治理门禁验证通过：`python3 .agents/scripts/gates/verify_agent_gates.py`。

## Risks

- **待验证假设**：真机环境下 `media_rw_data_file` 在 OEM 定制 ROM 中的写入策略定义，保留 `image_context` 配置项作为备选覆盖。
- **时序依赖**：修改标签必须在内核写 `lun.N/file` 前完成，已挂载中的 LUN 不会动态刷新标签生效。

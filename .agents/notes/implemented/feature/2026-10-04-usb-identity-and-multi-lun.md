# Agent Note: 多 LUN、每槽独立参数与 USB 设备身份

Status: implemented
Category: feature

## Problem

单 LUN 架构存在多项功能与架构限制：无法支持多介质并发导出（例如磁盘镜像与 CD-ROM 光盘镜像组合分发）；卸载单个镜像必须彻底拆除整条 USB 链路；且 USB 设备身份描述符固定沿用 Android 系统默认 MTP 参数，缺乏定制能力。

深入核对 Linux 主线内核代码可知：并非所有 configfs 操作均要求 UDC 处于非绑定状态。过度解绑 UDC 反而会拉长 Android init 介入重配的窗口，引发总线枚举死锁（代码 10）。

## Proposal

### 1. 多 LUN 独立槽位架构

每个 LUN 对应独立的逻辑单元，享有独立的 `rw` / `ro` / `cdrom` 模式与 SCSI INQUIRY 标识。

`mass_storage.rs` 划分为准备阶段与条件性紧凑段：
- 针对已有 LUN 的镜像、模式及 INQUIRY 变更，执行 `forced_eject` 后直接更新属性，全程无需断开 UDC 总线连接，规避抢占风险；
- 仅在新增 LUN 目录等结构性变更时才进入解绑与重建链路；
- 系统上限设为 `paths::MAX_LUNS = 8`。

### 2. 介质互斥与数据安全约束

同一镜像严禁同时作为两个 LUN 的后端，亦禁止同时处于 USB 导出与本地 loop 挂载状态。校验在写 configfs 前完成，判据严格基于内核实际状态。

### 3. USB 设备身份解耦与回读校验

- 描述符配置持久化于 `config/gadget.json`，字段均为可选；
- 写入后执行逐项回读校验，确保 configfs 实际生效；
- 仅在最后一个 LUN 被弹出时才原子恢复 Android 原生 USB 描述符；
- 挂载阶段主动关闭 `os_desc/use`，防止 Windows 驱动枚举冲突。

### 4. 字符串描述符编码与字段约束

| 字段 | 编码规则 | 约束依据 |
|---|---|---|
| `manufacturer` | UTF-8 编码，字节数 ≤126，无控制字符 | 内核经 `utf8s_to_utf16s` 完成转换，用于展示文本 |
| `product` | 同上 | 同上 |
| `serial` | 限制为可打印 ASCII 字符 | 避免 Host 端操作系统驱动枚举失败 |

长度以 UTF-8 字节数为准（上限 126 字节），兼容多字节字符在内核中的转换。

### 5. 身份保存与连接生命周期解耦

保存身份时不触发 USB 断开或 UDC 重新绑定，配置默认于下次连接时生效，避免热更新引起 USB 拓扑反复抖动。提供显式 `rebind` 命令作为手动逃生通道。

## Alternatives considered

- **所有参数变更均断开 UDC**：否决。拉长 init 抢占窗口，增加枚举互锁风险。
- **依赖覆写 `lun.N/file` 切换介质**：否决。内核在首次写入时锁定后备文件，覆写不会刷新已挂载 LUN 的容量元数据，必须经由 `forced_eject`。
- **全量卸载删除 LUN 目录**：否决。导致配置参数丢失，再次挂载需重复配置。
- **保存身份时自动重绑 UDC**：否决。自动解绑会造成 USB 连接闪断，且系统 init 重新介入将覆写已写入的属性。
- **移除手动 rebind 接口**：否决。保留显式手动重绑作为免插拔生效的调试入口。
- **序列号允许非 ASCII 字符**：否决。实机环境下非 ASCII 序列号会导致部分主机驱动无法识别枚举。

## Acceptance criteria

1. 单测覆盖多 LUN 独立参数与时序约束。
2. 身份属性单测通过：可选字段写入、UTF-8 中文产品名兼容、非 ASCII 序列号拒绝、126 字节上限精确校验。
3. 源码扫描测试通过，断言保存身份路径不触发自动重绑，且完整保留 `image_context`。
4. AVD 端到端验证：多 LUN 并发挂载各具独立模式，中文产品名回读一致，保存身份前后 UDC 保持稳定绑定。
5. 治理门禁验证通过：`python3 .agents/scripts/gates/verify_agent_gates.py`。

## Risks

- **主机重新枚举时机**：若特定操作系统在拔插 USB 时未重新请求字符串描述符，需引导用户使用手动 `rebind`。
- **序列号 ASCII 约束分析**：虽与产品名字段规则不一致，但优先保证与主流操作系统驱动栈的枚举兼容性。

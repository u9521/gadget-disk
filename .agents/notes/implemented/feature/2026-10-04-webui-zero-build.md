# Agent Note: 零构建 WebUI 的分层、通道契约与任务反馈

Status: implemented
Category: feature

## Problem

WebUI 为模块唯一交互界面，必须满足零构建（Zero-build）约束：严禁引入 Node 打包工具链、编译型框架及外部 CDN 依赖，实现全功能离线分发。此约束面临四项工程挑战：

1. **自动化单测保障缺失**：缺少端到端浏览器测试运行器，若数据解析与 DOM 操作耦合，则异常分支（执行超时、空输出、JSON 畸形）无法建立回归防线；
2. **`ksu.exec` 原生回调契约适配**：不同管理器版本签名存在兼容性差异；
3. **异步状态缺乏即时反馈**：亚秒级操作缺乏操作中（busy/pending）状态指示，易引发重复点击与并发竞态；
4. **分区解析缺失**：早期实现仅读取创建期偏移缓存，导致外部导入镜像因缺少分区表解析而挂载失败。

## Proposal

### 1. 严格逻辑与 DOM 分层

源码位于顶层 `webui/`，打包时同步复制为模块 `webroot/`（排除 `tests/`）：

- **`pure/` 纯函数层**：隔离所有数据解析、错误归一化、参数组装与容量校验，禁止访问 DOM 或浏览器特有 API，通过 Node 原生测试运行器执行自动化单测；
- **`view-*.js` 视图绑定层**：收敛事件监听、DOM 渲染与异步生命周期，六个视图各一模块；
- **`ksu.js` 桥接封装层**：封装原生调用为 Promise 契约。

模块必须**平铺在 `webui/` 顶层**（`pure/` 是唯一登记的子目录）：打包脚本只非递归扫描顶层，
放进子目录会本机测试全绿、打包却丢文件。完整模块清单与拆分理由见
[分块上传与前端扁平模块化](../architecture/2026-10-07-chunked-upload-and-flat-webui.md)。

### 2. `ksu.exec` Promise 永不 reject 约定

桥接层统一将调用结果封装为 `{errno, stdout, stderr}` 标准结构，捕获底层异常并映射为 `errno = -1`，杜绝未捕获异常导致前端白屏。`resolveBin` 严格按对象结构解析返回值，禁止直接调用字符串方法。

### 3. 双通信通道容灾设计

- **主通道**：本地回环 REST API（`gadgetdisk serve`），通过 `webroot/api.json` 投递高熵 Bearer Token；
- **降级通道**：`ksu.exec` + CLI 命令行执行。当服务未启动、空闲超时或异常退出时，自动无缝降级至 CLI，保证全功能可用。

### 4. 状态反馈与防重入机制

写操作触发时立即进入 busy 状态（设置 `aria-busy="true"` 并锁定触发控件），并在卡片内展示实时执行耗时。所有异步流程在 `finally` 块中统一定向清理，杜绝状态锁死。

### 5. 分区表解析由本仓库纯函数负责

集成纯函数 GPT/MBR 分区表扫描能力，单分区与多分区镜像均可动态识别可用分区偏移并填充
UI 下拉列表，不再单纯依赖创建期静态缓存。**用户态解析，不经内核 partscan**——后者在
Android 上恒回退且不可靠，已整体移除，理由见
[loop 挂载语义](../architecture/2026-10-04-loop-mount-semantics.md)。

## Alternatives considered

- **引入前端打包工具链（Vite/Webpack）**：否决。违背零构建轻量化分发原则。
- **让 `exec()` 在底层失败时 reject**：否决。前端多个流程需统一消费返回结构，永不 reject 可确保异常处理收敛于业务分支。
- **依赖正则提取混杂输出中的 JSON**：否决。无法防御嵌套括号与字符串字面量冲突，改为括号栈深度扫描。
- **乐观更新界面状态**：否决。与严格依赖内核实际状态的准则冲突。

## Acceptance criteria

1. `node --test webui/tests/` 自动化测试全绿通过。
2. `parseExecResult` 针对各类异常分支测试通过，能准确还原错误码。
3. `structure.test.mjs` 静态断言通过：无外部 CDN 引用、无 `localhost` 硬编码、**每个模块逐一**
   通过 `node --input-type=module --check` 语法解析，且具名 import 都是目标模块真实导出的。
4. 真机/AVD 端到端验证：六大视图渲染正常、离线状态横幅与降级通道正常流转。
5. 治理门禁验证通过：`python3 .agents/scripts/gates/verify_agent_gates.py`。

## Risks

- **结构静态测试局限性**：文本断言仅能防范特定代码模式与语法破坏，组件真实交互仍须依赖真机集成测试。
- **离线判定容错权衡**：`errno === -1` 时采取保守断开策略并展示重试入口，优先保障操作幂等性与数据一致性。
- **同构产物容易只给一处加守护测试。** 两处实测踩到：
  1. `gadgetdisk --help` 有测试守，**`gdd --help` 没有**——于是它的选项继续以中文
     `///` 呈现。本机测试**全绿**，只有把 `--help` 打到设备上才看得见。修法是补一条
     同构测试（`help_is_english_and_non_empty`）。教训：**一处有了守护，同构的另一处
     必须一起加**，否则覆盖缺口正好落在没人看的那一侧。
  2. 中文扫描只匹配汉字，**漏掉纯标点**：脚本对齐输出用的全角冒号 `：`
     （`gd-build`/`gd-package`/`gd-deploy` 共 6 处）不在 `[一-龥]` 范围内。
- **零构建下没有类型系统兜底**，因此「两处字段名/两个同构产物必须一致」这类约束只能
  靠静态断言维护；上一条正是该手段覆盖不全时的表现。
